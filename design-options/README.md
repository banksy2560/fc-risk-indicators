# Site design options (design phase, not deployed)

Three self-contained static mockups (inline CSS/JS, one data blob, Google Fonts optional, light/dark via `prefers-color-scheme` plus a Theme toggle). All use real data: all 106 typologies and 177 controls with true reuse counts, plus full indicator detail for 12 diverse typologies (ML-MULE, ML-TBML, FR-APP, FR-ATO, SANC-DIVERSION, TF-NPO, BC-FBRIBE, HT-TRAFFICK, CY-RANSOM, TX-VATFRAUD, EC-WILDLIFE, PF-DUALUSE). Data is regenerated by a script kept outside the repo (scratchpad `design/build_data.py`). Open the files directly in a browser.

**Option A: Typology explorer (`option-a.html`).** A conventional reference-site layout: domain-grouped left navigation, a typology page with expandable indicators, each revealing its context, false-positive notes and linked controls (with "used in N typologies"), plus control pages that list every typology using them. Best for: practitioners learning or looking up a known typology, and anyone arriving from a link or citation. Tradeoffs: strongest on the typology-to-control direction; cross-cutting questions ("where is this control used?") take a click or two; least distinctive, and the left nav of 106 items needs the filter box.

**Option B: Coverage matrix (`option-b.html`).** A typology by control-family grid (all 106 x 19) with cell counts, drill-down panels for cells, rows and columns, and a reverse Controls view sorted by reuse. Best for: risk and compliance teams mapping their control framework to the library, and for showing the many-to-many structure at a glance. Tradeoffs: densest and the steepest learning curve; heat shading invites reading counts as coverage quality or risk (mitigated with explicit legend and wording, but this remains the main product risk); weakest on phones and for first-time visitors.

**Option C: Search-first catalogue (`option-c.html`).** A command-palette style home: one large search box (press `/`), facets for domain, indicator category, control type, control family and sector, mixed result cards for typologies, indicators and controls, and a detail drawer that lets you hop between linked items with Back. Best for: users who arrive with a keyword (a red flag, a control name) and for contributors checking whether something already exists before adding a duplicate. Tradeoffs: weak sense of structure for people who do not know what to search for; the drawer navigation hides the hierarchy; needs a good search index at 654 indicators (client-side is fine at this size).

**Recommendation: C as the front door, with A's typology page as the destination.** The library's value is two-way linking and de-duplication, and most visits will start from a term or a control name, which search and facets serve best; the drawer already demonstrates the typology, indicator and control hops. Typology remains the unit of analysis, so each typology should still have a stable, citable, full page (A's layout) rather than living only in a drawer. Keep B as a secondary "Coverage" page for compliance users once the content is reviewed, since a count matrix can be over-read while content is v0.1 and unreviewed.
